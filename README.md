# Классификация тональности отзывов

Практическое задание 4 недели курса: определение тональности пользовательских
отзывов на фильмы - негативный / нейтральный / позитивный.

## Задача

Сервис онлайн-показа фильмов хочет автоматически определять тональность
отзывов, чтобы в дальнейшем рекомендовать фильмы с наибольшим количеством
хороших отзывов. Решение - классический пайплайн анализа тональности:
NLP-предобработка + векторизация текста + классик ML-модель

## Датасет

[ai-forever/kinopoisk-sentiment-classification](https://huggingface.co/datasets/ai-forever/kinopoisk-sentiment-classification)
на HuggingFace. Три jsonl-файла с полями `text` и `label`:

| label | класс      |
|-------|------------|
| 0     | негативный |
| 1     | нейтральный|
| 2     | позитивный |

| выборка    | размер |
|------------|--------|
| train      | 10 500 |
| validation | 1 500  |
| test       | 1 500  |

## Подход

**Предобработка** (`process.py` / `service/preprocessing.py`):
- приведение к нижнему регистру;
- `!`, `?`, `...` заменяются на псевдо-токены (ВОСКЛИЦАНИЕ / ВОПРОС /
  МНОГОТОЧИЕ) - эмоциональная окраска пунктуации не теряется при дальнейшей
  очистке (решил так сделать для улучшения значения метрик);
- удаление прочей пунктуации;
- лемматизация через `pymystem3` (Yandex Mystem) - вместо предложенного в ТЗ
  `pymorphy3`, так как Mystem лемматизирует по контексту всего предложения, а
  не пословно;
- удаление стоп-слов с **исключением "не"**;
- склейка отрицания со следующим словом (`не` / `ни` + слово → `не_слово`),
  чтобы модель не теряла смысл при удалении отрицательной частицы как
  отдельного токена

**Векторизация**: `TfidfVectorizer` 

**Модели**: `LogisticRegression` и `LinearSVC`

## Результаты на тестовой выборке

| Модель               | Accuracy | Precision (macro) | Recall (macro) | F1 (macro) |
|-----------------------|----------|--------------------|-----------------|------------|
| TF-IDF + LogisticRegression | 0.66 | 0.65 | 0.66 | 0.65 |
| TF-IDF + LinearSVC          | 0.67 | 0.65 | 0.67 | 0.65 |

Подробный отчёт по классам (`classification_report`) выводится при запуске
`train.py`. Обе модели заметно хуже разделяют нейтральный класс (F1 ≈ 0.5),
чем негативный и позитивный (F1 ≈ 0.7–0.8) - нейтральные отзывы по тексту
объективно ближе к соседним классам

## Выводы

- LogisticRegression и LinearSVC показали практически одинаковое качество
  (accuracy 0.66–0.67, macro F1 0.65) - выбор векторизации и предобработки
  влияет на результат сильнее, чем выбор между этими двумя линейными
  моделями
- Основной источник ошибок - нейтральный класс, который путается как с
  негативным, так и с позитивным
- Для сервиса выбрана **LogisticRegression**, так как она отдаёт калиброванные
  вероятности классов, что требуется по условию задания, тогда
  как `LinearSVC` для этого нужно дополнительно обрабатывать

## Как велась работа

Baseline (TF-IDF на униграммах + LogisticRegression с дефолтными параметрами)
давал около 0.66 на validation. Дальше пробовал разные вещи, чтобы поднять
качество

Финальная модель - LogisticRegression с `C=100, class_weight='balanced'` поверх
TF-IDF (`min_df=5, max_df=0.85`, униграммы+биграммы), 0.69 на validation.
На test вышло чуть меньше, 0.65-0.66 - часть параметров (включая C) подбиралась
именно по validation, поэтому там результат немного оптимистичнее, чем на
незнакомых данных

**Что реально помогло:**

- Добавил биграммы, а не только отдельные слова - небольшой прирост
- Обрезал словарь TF-IDF через `min_df`/`max_df` (выкинул слишком редкие и
  слишком частые слова) - тоже небольшой прирост, но тут легко перестараться:
  если сделать `min_df` слишком строгим, вместе с мусором вырезаются полезные
  биграммы
- `class_weight='balanced'` - заметно подтянул recall на "Нейтральном" классе
- Подбирал `C` через GridSearch, но не через кросс-валидацию, а через
  `PredefinedSplit` на реальной validation-выборке - так и нашёлся C=100 вместо C=1
- Не стал выкидывать знаки препинания полностью - заменил `!`, `?`, `...` на
  отдельные токены-метки (ВОСКЛИЦАНИЕ/ВОПРОС/МНОГОТОЧИЕ). Прирост был, но не большой
- Склейка отрицания со следующим словом (`не`/`ни` + слово → `не_слово`) дала
  самый заметный эффект из всего списка, особенно на "Нейтральном" классе
  (F1 подрос до 0.55 на validation)

**Что пробовал, но не сработало:**

- Расширял список исключений из стоп-слов (добавлял "но", "хотя", "очень" и
  т.п., чтобы они не удалялись) - эффекта не было, вернул как было
- Собирал ансамбль (`VotingClassifier` из LogReg + SVM + NaiveBayes) -
  результат остался на уровне лучшей одиночной модели, ансамбль не помог

## Как воспроизвести обучение

1. Установить зависимости:
   ```bash
   pip install -r requirements.txt
   python -m nltk.downloader stopwords
   ```
2. Скачать `train.jsonl`, `validation.jsonl`, `test.jsonl` со страницы
   [Files and versions](https://huggingface.co/datasets/ai-forever/kinopoisk-sentiment-classification/tree/main)
   датасета в папку `training/`.
3. Из папки `training/` запустить:
   ```bash
   python process.py   
   python train.py     
   ```
   При первом запуске `pymystem3` скачивает бинарник Mystem — нужен
   доступ в интернет
4. Скопировать `model_logreg.joblib` и `vectorizer_logreg.joblib` в `service/`,
   если модель переобучалась

## FastAPI-сервис

Запуск:
```bash
cd service
uvicorn main:app --reload
```

Пример запроса:
```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "Отличный фильм, давно так не смеялся!"}'
```

Ответ:
```json
{
  "label": 2,
  "label_name": "Хороший",
  "probability": 0.9639,
  "probabilities": {
    "Плохой": 0.0002,
    "Нейтральный": 0.0359,
    "Хороший": 0.9639
  }
}
```

`GET /health` — проверка живости сервиса
